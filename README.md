# WorkDBFform — загрузка DBF в SQL Server

Программа берёт DBF-файлы (FoxPro, dBase, Clipper) из папки и загружает их в базу SQL Server:
**один файл — одна таблица**. `NACI29.DBF` попадает в таблицу `dbo.NACI29`.

Основное назначение — ежедневное обновление базы по расписанию (через Планировщик заданий Windows):
программа запускается без окна, загружает новые таблицы (а с `/replace` — и обновляет изменившиеся),
пишет журнал и закрывается.
Для ручной загрузки есть окно.

## Что программа делает с каждым файлом

- создаёт таблицу `dbo.<ИМЯ_ФАЙЛА>` с типами столбцов по заголовку DBF; все столбцы допускают NULL;
- если таблица уже есть — **по умолчанию пропускает её**; с `/replace` заменяет свежими данными,
  но только если DBF изменился с прошлой загрузки (с `/replace /all` — заменяет всегда);
- пропускает записи, помеченные в DBF на удаление, и полностью пустые строки;
- битые числа и даты записывает как NULL и считает их в журнале;
- в конце сверяет число загруженных строк с `COUNT(*)` в таблице.

Каждая таблица загружается в отдельной транзакции: если загрузка файла сорвалась,
в базе остаётся прежняя версия таблицы, а остальные файлы продолжают загружаться.

## Требования

- Windows с .NET Framework 4.8 (есть в Windows 10 и 11);
- SQL Server; вход — под учётной записью Windows, которая запускает программу.
  Ей нужны права на создание таблиц в базе и на чтение папки с DBF.

Python, ODBC-драйверы и дополнительные библиотеки не нужны.

## Установка

Скопируйте в постоянную папку, например `C:\DbfLoader`, два файла из `WorkDBFform\bin\Release`:

- `WorkDBFform.exe`
- `WorkDBFform.exe.config` — необязателен, см. «Параметры в конфиге».

## Запуск с параметрами (без окна)

```
WorkDBFform.exe <папка или файлы> <база> [сервер] [/replace] [/all] [/quiet]
```

Примеры:

```
WorkDBFform.exe D:\NAS "ГНИ \"Слободзея\"" localhost
WorkDBFform.exe D:\NAS\NACI29.DBF D:\NAS\NACH29.DBF "ГНИ \"Слободзея\""
WorkDBFform.exe \\server\share\NAS MyBase .\SQLEXPRESS /replace
```

| Параметр | Обязателен | Что означает |
|---|---|---|
| папка или файлы | да | Что загружать. Папка просматривается вместе с вложенными. Можно указать несколько папок и/или отдельных `.dbf` через пробел. |
| база | да | Имя базы так, как оно показано в SSMS. |
| сервер | нет | Например `localhost` или `.\SQLEXPRESS`. По умолчанию — `Server` из конфига, а если его нет — `localhost`. |
| `/replace` | нет | Заменять таблицы, которые уже есть в базе, если их DBF изменился с прошлой загрузки. Без этого параметра существующие таблицы пропускаются. |
| `/all` | нет | Вместе с `/replace`: заменять все существующие таблицы, даже если DBF не менялся. |
| `/keep` | нет | Пропускать существующие таблицы, даже если в конфиге `Replace=true`. |
| `/quiet` | нет | Не показывать окно с итогом после загрузки (только журнал). |
| `/gui` | нет | Открыть окно вместо загрузки без окна. |
| `/?` | нет | Показать подсказку по параметрам. |

Как программа различает параметры: всё, что похоже на путь (существующая папка или файл, путь
с `:\`, путь вида `\\сервер\...` или имя на `.dbf`), — это то, что загружать. Первое слово, не похожее
на путь, — имя базы, второе — сервер. Поэтому опечатка в пути не превратится в имя базы:
в журнале появится «не найдена папка или файл».

**Пробелы и кавычки.** Значение с пробелами берётся в кавычки. Кавычки внутри значения пишутся
с обратной косой чертой: база `ГНИ "Слободзея"` записывается как `"ГНИ \"Слободзея\""`.

## Параметры в конфиге

Файл `WorkDBFform.exe.config` рядом с exe, раздел `<appSettings>`:

```xml
<add key="Folder"        value="" />
<add key="Database"      value="" />
<add key="Server"        value="localhost" />
<add key="Replace"       value="false" />
<add key="SkipUnchanged" value="true" />
<add key="ShowResult"    value="true" />
```

| Ключ | По умолчанию | Что означает |
|---|---|---|
| `Folder` | пусто | Что загружать при запуске **без параметров**. Несколько папок или файлов — через `;`. |
| `Database` | пусто | База для запуска без параметров. Кавычки внутри имени записываются как `&quot;`: `ГНИ &quot;Слободзея&quot;`. |
| `Server` | `localhost` | Сервер, если он не указан в параметрах запуска. |
| `Replace` | `false` | `false` — пропускать таблицы, которые уже есть; `true` — заменять их свежими данными (как `/replace`). |
| `SkipUnchanged` | `true` | Действует при `Replace=true`: `true` — не заменять таблицы, чей DBF не менялся; `false` — заменять все (как `/all`). |
| `ShowResult` | `true` | `true` — после загрузки без окна показать сообщение с итогом; `false` — не показывать (как `/quiet`). |

Логические значения можно писать как `true`/`false`, `1`/`0` или `да`/`нет`.

### Что важнее

- Параметры запуска важнее конфига: папка, база и сервер из командной строки заменяют значения из конфига,
  флаги `/replace` и `/keep` — значение `Replace`, `/all` — `SkipUnchanged`, `/quiet` — `ShowResult`.
- Запуск **без параметров**: если в конфиге заполнены `Folder` и `Database` — загрузка без окна,
  если пустые — открывается окно.
- Без конфига программа тоже работает: используются значения по умолчанию из таблицы выше.

## Ежедневный запуск по расписанию

1. Проверьте команду вручную в командной строке и посмотрите журнал.
2. Откройте Планировщик заданий (Win+R → `taskschd.msc`) → «Создать простую задачу…».
3. Триггер — «Ежедневно», время — например 06:00. Действие — «Запустить программу»:

   | Поле | Значение |
   |---|---|
   | Программа или сценарий | `C:\DbfLoader\WorkDBFform.exe` |
   | Добавить аргументы | `D:\NAS "ГНИ \"Слободзея\"" localhost` |
   | Рабочая папка | `C:\DbfLoader` |

   С такими аргументами каждый запуск загружает только **новые** таблицы. Чтобы ежедневно обновлять
   и уже загруженные (если их DBF изменился), добавьте в конец аргументов `/replace`.

4. В свойствах задания выберите «Выполнять для всех пользователей» и введите пароль учётной записи —
   тогда задание работает, даже когда никто не вошёл в систему.

Если DBF лежат на другом компьютере, указывайте сетевой путь `\\компьютер\папка`, а не букву
подключённого диска: у заданий планировщика подключённых дисков нет.

## Журнал и результат

После загрузки без окна появляется сообщение с итогом: сколько файлов загружено и сколько строк,
сколько пропущено без изменений, сколько с ошибками (с именами таблиц) и где журнал.

- Сообщение показывается, только если программа запущена на рабочем столе пользователя: вручную
  или заданием «Выполнять только для пользователей, вошедших в систему». Задание «Выполнять для всех
  пользователей» работает в фоне, и сообщение там не появляется — смотрите журнал.
- Если сообщение никто не закрыл, оно закрывается само через 30 минут, чтобы задание не «висело»
  и следующий запуск не пропустился.
- Отключить сообщение: параметр `/quiet` или `ShowResult=false` в конфиге.

Каждый запуск без окна дописывает отчёт в `WorkDBFform.log` рядом с exe (если туда нельзя писать —
в `%LOCALAPPDATA%\WorkDBFform\WorkDBFform.log`). По каждому файлу видно, сколько строк загружено,
сколько удалённых и пустых записей пропущено, сколько битых значений заменено на NULL.

Код завершения (в Планировщике — столбец «Результат последнего запуска»):

| Код | Значение |
|---|---|
| 0 | Всё загружено без ошибок. |
| 1 | Часть таблиц загрузилась с ошибками — подробности в журнале. |
| 2 | Загрузка не запустилась: файлы не найдены или нет подключения к серверу. |

## Служебная таблица `dbo._DbfLoadHistory`

Программа создаёт её в базе сама. В ней по каждой таблице хранится, из какого файла и когда она
загружена, сколько строк и «отпечаток» файла (размер и время изменения DBF и его .FPT/.DBT).
По отпечатку программа решает, изменился ли файл с прошлой загрузки. Если удалить строку из этой
таблицы (или саму таблицу с данными), файл загрузится заново при следующем запуске.

## Окно программы

Открывается при запуске без параметров (если в конфиге не заданы `Folder` и `Database`),
с параметром `/gui` или если перетащить файлы на значок программы.

- «Добавить файлы…» (можно выбрать несколько), «Добавить папку…», перетаскивание файлов и папок
  в окно; клавиша Delete убирает выделенные файлы из списка.
- «Сервер», «База», галочка «Пересоздавать таблицы, которые уже есть».
- «Загрузить» — загружает выбранные файлы **полностью**, без проверки на изменения.
- Сервер, база и последняя папка запоминаются между запусками.

## Особенности

- **Имена таблиц** берутся из имени файла. Файлы с символами кроме латиницы, цифр и `_`
  (например, резервные копии `TIPIM---.DBF`) пропускаются. Если в разных папках есть файлы
  с одинаковым именем, загружается первый найденный, остальные отмечаются в журнале.
- **Кодировка** DBF — cp866 (DOS-кириллица).
- **Memo-поля** читаются из файла .FPT или .DBT рядом с DBF; если его нет — значения будут NULL.
- **Маски** вида `NACI*.DBF` не поддерживаются — укажите папку или файлы явно.

Типы столбцов:

| Поле DBF | Тип в SQL Server |
|---|---|
| C (текст) | `nvarchar(длина)` |
| N, F с дробной частью | `decimal(длина, знаки)` |
| N, F без дробной части | `smallint` / `int` / `bigint` — по длине поля |
| D (дата) | `date` |
| T (дата и время) | `datetime2` |
| L (логическое) | `bit` |
| I (целое) | `int` |
| B, O (дробное) | `float` |
| Y (деньги) | `decimal(19,4)` |
| M (memo) | `nvarchar(max)` |

## Сборка

Откройте `WorkDBFform.sln` в Visual Studio и соберите конфигурацию **Release**.
Готовые файлы — в `WorkDBFform\bin\Release`.

Код:
- `DbfReader.cs` — чтение DBF и memo-файлов;
- `DbfLoader.cs` — загрузка в SQL Server;
- `Program.cs` — разбор параметров и запуск без окна;
- `Form1.cs` — окно.
